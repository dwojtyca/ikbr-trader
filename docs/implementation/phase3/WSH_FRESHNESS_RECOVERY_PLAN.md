## Current source and bounded change

`packages/shared/src/instrument-research/wsh.ts` fixes both `refreshIntervalMs` and `maxAgeMs` at 900000. `eligibility.ts` and `repair.ts` independently hardcode that age. `apps/llm-agent/src/research-wsh-refresh.ts` removes the previous WSH projection before acquisition and publishes negative coverage on failure. `ResearchStore.finishWshFailure` moves the latest head to that negative snapshot. `assertWshSnapshotProvenance` correctly requires the entire successful coverage/evidence/events projection to equal its original PUBLISHED acquisition; this invariant stays.

`ResearchStore.beginWshAcquisition` currently rejects every acquisition for the issuer ledger within 15 minutes, including after failure. `prepareRepair`, scheduler `attemptedSlots`, and `research_refresh_slots` independently prevent same-slot retries. Acquisitions start only after transport connection, so acquisition rows alone cannot bound connection failures across restarts. The transport already cancels owned requests, waits a bounded time for local SDK sends, and disconnects; it does not prove broker acknowledgement. These are actual integration points, not a timeout tuning task.

Scope is WSH only, within one exact current configuration/manifest/instrument/source. No Marketaux/report eligibility changes, timeout enlargement, source entitlement extension, broker order retries, synthetic proposals or risk changes. Reuse across different manifest hashes—even when only unrelated news settings changed—is deferred: current durable provenance explicitly disallows it. This release therefore still requires fresh WSH after a new manifest adoption.

## Evidence and freshness contract

1. Keep schema/version and legacy canonical bytes readable. `WshConfig.maxAgeMs` accepts exactly 900000 or 86400000; `refreshIntervalMs` remains exactly 900000. Existing manifests retain their original 15-minute semantics. A newly reviewed private manifest may select 86400000. Do not reinterpret old hashes or add implicit defaults to serialized legacy objects.
2. Both eligibility and preparation use the parsed WSH `maxAgeMs`, from the same helper. A successful AVAILABLE or EMPTY calendar is usable only while `now < original checkedAt + maxAgeMs`, with unchanged qualification/entitlement deadlines, identity, permission, request, provenance and all other research gates. Equality is stale. A 24-hour TTL never extends a qualification deadline or makes future timestamps valid. The request horizon and FIRST_OBSERVED semantics stay unchanged.
3. On an explicitly classified transient read failure, retain the latest head's existing WSH coverage/evidence/events byte-for-byte, including `checkedAt`, request/receipt times, acquisition identity, first observations and event versions. Do not attach failure fields to that immutable projection. If no success exists, retain/publish negative coverage as appropriate. If successful evidence has expired, it may remain stored but cannot grant readiness.
4. Persist each refresh attempt and its latest original sanitized error separately from usable snapshot evidence. When a valid calendar survives a transient failure, preparation is READY with an explicit nonblocking refresh diagnostic, last successful check, effective expiry, last failure time/stage and next retry/regular time. The error remains visible after retries are exhausted until a later successful refresh supersedes the current diagnostic; all attempt history remains queryable. No wording claims a fresh successful fetch. Diagnostic text is never an eligibility instruction or reason classifier.
5. Hard failures publish a negative WSH projection through the existing head-changing path, invalidate bound-head evidence as today, and cannot fall back to an earlier success. Hard failures include identity/account/endpoint/metadata mismatch; missing/expired permission or qualification; malformed/truncated/inconsistent payload; request/protocol/schema/provenance/hash errors; and unclassified provider/implementation failures. A later transient failure cannot resurrect pre-hard-failure data. Only a new fully validated acquisition can restore usable coverage.
6. Explicit soft classification: existing WSH timeout and disconnected transport failures, and connection failure with known provider code 502, qualify for retained evidence and potentially fast retry. A send failure qualifies only when its preserved typed underlying cause proves a transport connection failure; generic SEND_FAILED is not enough. Reviewer-accepted exact send-boundary code allowlist: ECONNRESET, ECONNREFUSED, ENOTCONN, EPIPE, ETIMEDOUT, or preserved numeric provider502. Match only validated original typed cause/sourceError.code for SEND_FAILED, never message/name, substring, numeric-string coercion or unrelated phase. CONNECT_FAILED remains provider502-only. Tests cover each positive and generic/text-only/wrong-phase/unknown negatives. Code 10281 is observable busy/cleanup uncertainty: retained still-valid success is allowed, but no fast retry; preserve the original code/message and wait for ordinary recovery. Shutdown abort retains prior evidence, schedules no fast retry. Unknown provider codes default hard/unclassified, not a broad regex allowance. Budget exhaustion changes acquisition scheduling, not the validity of already accepted evidence; it never authorizes an extra call.

## Durable scheduling and cleanup contract

One regular cycle per `wshLedgerKey(isin)`, across endpoints/processes/manifests, starts no earlier than 900000 ms after the preceding regular cycle began. Use database time. Retry success or failure does not move that next regular deadline. Each cycle has initial attempt ordinal 0 and at most two extra attempts, ordinals 1 and 2. Retry 1 is due 30000 ms after verified local cleanup completion; retry 2 is due 120000 ms after its predecessor's verified local cleanup completion. A retry cannot start at/after the cycle's next regular deadline. No catch-up loop: at most one eligible attempt is claimed at a time; missed opportunities are not replayed. Global issuer admission excludes every still-active attempt across endpoints/manifests, not merely on one endpoint. A late retry whose bounded deadline overlaps next_regular_at blocks the next regular cycle until terminal settlement or fenced abandonment recovery; changing endpoints cannot create overlap. Timeout expiry alone is not proof of transport cleanup or permission for fast retry.

A durable attempt is reserved before connecting, so DNS/connect/handshake failures consume an ordinal even without a provider call. Retries require the same original manifest/source identity and a retryable predecessor; adopting another manifest cannot mint extra retries or reset issuer pacing. Each retry is a new read acquisition/session and fresh request hashes, linked to its original cycle and prior failed attempt. This is an explicitly bounded new read, not replay of an unknown order/model submission or revision of an earlier UNKNOWN outcome. Every metadata/event request still obtains the existing immutable budget reservation; no refunds, budget reset or reserved-call reuse. At most six charged WSH requests per cycle (three attempts, each metadata plus events); fewer when failures occur earlier. Existing provider budgets can reduce this bound.

Fast retry requires all of: endpoint session lock still verified during settlement; prior acquisition durably retired; no PENDING generation; owned request cancellation attempted once in event-before-metadata order; bounded cleanup completed; local disconnect observed/confirmed by the owned transport; and no cleanup uncertainty. SDK `sent` is only local write-attempt evidence, never broker ACK. Define cleanup result explicitly rather than swallowing failure as success. The installed SDK public disconnected callback is also emitted for peer end and is not sufficient local-close proof. Permit one narrow pinned SDK1.6.10 production-adapter seam capturing its actual Node socket identity immediately after connect (also after a thrown connect that allocated a socket). Observe the actual Node close event or closed===true; destroyed alone, peer end and SDK disconnected do not qualify. A local destroy of that exact owned socket is allowed after normal bounded cancellation/disconnect cleanup to ensure local resource closure; it is not broker cancellation. Expose only typed local socket lifecycle capabilities to the transport, never raw SDK internals to business logic. Missing capability, changed socket identity or absent actual close yields UNKNOWN/no fast retry. A connect never attempted and no socket ever allocated is separately NOT_NEEDED, not a fabricated close. Never invent cancellation acknowledgement. Preserve the current 750 ms cancellation-send wait and 25 ms local grace. Add at most 1000 ms total for actual local-close confirmation after that existing cleanup, including the owned-socket destroy fallback; exhausting it yields UNKNOWN. This bounds local cleanup to 1775 ms, does not lengthen any provider call (still at most 10000 ms), and does not authorize another remote send. Verified NOT_NEEDED cleanup before any socket was allocated may permit a classified transient connect retry; lack of inspection capability is UNKNOWN, not NOT_NEEDED.

A crash, lost lease, failed cancellation, unconfirmed close, 10281, or ambiguous terminal commit disables fast retry for that predecessor. Recovery under the endpoint lock may retire abandoned state UNKNOWN exactly as current recovery permits; it does not manufacture a cleanup-confirmed receipt. Ordinary 15-minute acquisition remains possible only after existing recovery/fencing and budget checks. No client-ID rotation, global reset, cancellation of another process's requests, or claim that 10281 is impossible. Late callbacks from prior generations cannot publish, schedule retries, or alter newer outcomes. A successful acquisition may already have published before final cleanup; keep that proven content and settle its attempt with the actual cleanup result. Unconfirmed cleanup still fences endpoint/issuer reuse and grants no fast retry, even when content is usable. A failed cleanup must not relabel a proved PUBLISHED acquisition FAILED or alter its original call outcomes. If publication acknowledgement is uncertain, exact existing acquisition/snapshot readback is required before treating that success as proved; absent proof keeps the uncertainty hold. Persist this distinction before releasing admission so another worker cannot rely on a process-local close promise.

Scheduler regular refresh and faster retries are separate paths: regular `attemptedSlots`/`hasRefreshSlot` remain effective; the retry path uses durable attempt ordinal identities and must not delete or forge regular slot records. The existing 2-second repair tick can inspect due WSH attempts, including when retained evidence keeps preparation READY; it must not require a demand WAITING row or create an entry proposal. Endpoint lock contention is no-op/defer, not a consumed network attempt. Fair bounded selection must let another instrument run rather than repeatedly choosing a busy issuer. A stopped scheduler never starts another attempt.

## Persistence/API contract and ownership boundary

Add `infra/sql/migrations/000033_wsh_refresh_recovery.sql` (recheck next available number before implementation), with database constraints and isolated PostgreSQL fixtures. Keep existing acquisitions, immutable snapshots, refresh slots and call outcomes; do not backfill fabricated attempts, modify old timestamps or rewrite UNKNOWN history.

New durable cycle/attempt records:

- Cycle: UUID, issuer `ledger_key`, exact config/manifest/instrument/source identity, source-policy hash, `started_at` and `next_regular_at` from DB time. Unique cycle identity and serialized issuer admission; `next_regular_at = started_at + 15 minutes`.
- Attempt: UUID, cycle FK, ordinal 0..2 unique per cycle, predecessor FK for retries, endpoint ID, process/transport identity, started/deadline/finished times, optional acquisition ID, state STARTED/SUCCEEDED/FAILED/UNKNOWN, stable failure class/reason/stage, sanitized original cause and existing optional provider error, cleanup CONFIRMED/UNKNOWN/NOT_NEEDED with bounded local milestone timestamps, retry due time. Immutable terminal records; compare-and-set STARTED settlement only. No raw payloads, stacks, account identifiers or secrets in diagnostics.
- STARTED has a fixed 35000 ms durable deadline from DB attempt start, covering the unchanged maximum 30000 ms acquisition plus at most 1775 ms local cleanup and bounded bookkeeping; transport/provider deadlines remain unchanged. A result after its admission deadline cannot become successful merely because this recovery deadline remains open. All attempt bookkeeping statements use a bounded transaction-local timeout within the remaining 35000 ms budget; expiration leaves unresolved state for recovery rather than extending a lease. The durable deadline is not a provider timeout. A missing terminal result after that deadline is unresolved work, never evidence of success or retry permission. Its diagnostic/recovery status is read from DB, not an in-memory timer. Existing successful calendar can be used during an ordinary in-progress refresh; an overdue unresolved attempt must fail closed until exact readback proves its committed classified result or a later fully validated acquisition succeeds. Retiring an overdue/lost-lease/ambiguous attempt UNKNOWN alone never clears this uncertainty hold: a hard failure may have occurred before its outcome was persisted. Ordinary next-cycle recovery may perform a fresh read, but cannot serve the prior cache meanwhile. This prevents a crash during a hard-failure publication from silently presenting the old good head indefinitely.
- At migration, the latest legacy acquisition's started time still enforces its original 15-minute issuer spacing. Legacy failures do not acquire new fast-retry rights. New attempts must not reset that baseline.

Typed shared store boundary (final field names may be mechanical, semantics fixed):

```ts
type WshAttemptKind = 'regular' | 'retry';
type WshCleanupState = 'CONFIRMED' | 'UNKNOWN' | 'NOT_NEEDED';
interface WshAttemptTicket {
  id: string; cycleId: string; ordinal: 0 | 1 | 2;
  startedAt: string; deadlineAt: string; nextRegularAt: string;
  configHash: string; manifestHash: string; instrumentId: string;
  sourceId: string; endpointId: string;
}
type WshFailureClass = 'TRANSIENT' | 'HARD' | 'UNCERTAIN' | 'BUSY' | 'ABORTED' | 'BUDGET';
type WshFailureStage = 'connect' | 'metadata' | 'events' | 'normalize' | 'publish' | 'cleanup';
interface WshRefreshState {
  sourceId: string;
  lastSuccessfulAt: string | null;
  expiresAt: string | null;
  retained: boolean;
  latestAttempt: null | {
    id: string; cycleId: string; ordinal: 0 | 1 | 2;
    state: 'STARTED' | 'SUCCEEDED' | 'FAILED' | 'UNKNOWN';
    startedAt: string; finishedAt: string | null;
    failureClass: WshFailureClass | null;
    failureReason: string | null; stage: WshFailureStage | null;
    sourceError?: ResearchSourceError;
    providerError?: ResearchProviderError;
    cleanup: WshCleanupState;
  };
  latestFailure: WshAttemptDiagnostic | null; // Retained during STARTED retries until later success.
  nextRetryAt: string | null;
  nextRegularAt: string | null;
  blocksCachedEvidence: boolean;
}
type WshAttemptClaim =
  | { state: 'CLAIMED'; ticket: WshAttemptTicket }
  | { state: 'DEFERRED'; reason: string; nextCheckAt: string | null };
```

`ResearchSourceError`/`ResearchProviderError` are existing sanitized shared types; no arbitrary error object enters these records. `retained` means the latest failed attempt left an otherwise valid original good projection authoritative; it is not true for expired evidence or blocking uncertainty. `expiresAt` is the effective minimum of original checkedAt+configured age and qualification/entitlement expiry. `blocksCachedEvidence` is derived from durable current-identity attempt state and is never caller supplied. Stage is an allowlisted local phase, not interpolated provider text. `latestAttempt` terminal success replaces the current failure display, while prior attempt rows retain errors.

`claimWshAttempt(lease, exact identity, kind): Promise<WshAttemptClaim>` returns a ticket or bounded defer with nextCheckAt; uses DB time, issuer admission lock and current authority. It runs before connect, verifies original cycle/ordinal/predecessor and does not send. `beginWshAcquisition(lease, input, ticket)` binds the existing acquisition and immutable budget reservation to exactly that STARTED ticket; it replaces only the blanket 15-minute test with the accepted cycle/attempt predicate. `finishWshAttempt(lease, ticket, terminal result)` atomically settles attempt, retires/links acquisition and records failure diagnostic, plus either publishes negative/current success snapshot or retains the unchanged good head as specified. Existing ambiguous-publication readback must verify ticket, acquisition, snapshot/head action and terminal result before declaring settled. Unknown commit is read back once by exact identity; never blindly retry publication or send.

`readWshRefreshState(identity, db?): Promise<WshRefreshState>` returns typed last-success/expiry, latest attempt and sanitized diagnostic, due retry/regular time, and unresolved/hard status. `dueWshAttempts(current authority): Promise<Array<{ identity: ResearchRepairIdentity & { sourceId: string }; kind: WshAttemptKind; dueAt: string }>>` returns at most two fairly ordered due rows per call; recheck authority/admission under claim lock. It does not reserve/send by itself. These are used by existing `prepareRepair`, eligibility/store authority checks, and scheduler. Pure eligibility still validates snapshot content; store-backed entry/binding/preparation must additionally reject overdue unresolved/hard attempt state. No DB-only exception can make a malformed snapshot eligible. `finishWshFailure` may remain as a compatibility/internal wrapper, but its previous mandatory negative-head behavior must be selected explicitly, not silently bypassed.

Transactions preserve lock order: existing authority/observations, endpoint row, issuer admission/cycle/attempt, budget, snapshot head; endpoint session lock outside transactions. Do not call a store transaction recursively on another pooled connection while holding these locks. If actual existing lock order conflicts, stop for reviewed amendment. Serialize head selection and settlement so simultaneous news/report refresh cannot overwrite newer WSH failure or resurrect an obsolete projection. Last-good selection is the current head under lock, never an arbitrary historical-success search. Provenance checks remain exact against the original PUBLISHED acquisition; retained success does not relink that acquisition to the failed attempt.

### Accepted final-review repair amendments

Independent reviewer `stale_alert_plan_review` accepted these bounded clarifications before repair implementation:

- Every terminal cleanup UNKNOWN on the same endpoint **or** issuer, including SUCCEEDED and other accounts/manifests, fences later acquisition. Explicit `verifiedLocalClosure` is independent of timestamps: it certifies the exact captured original socket remained identifiable and actual close/closed was observed, with no missing capability or replacement ambiguity. UNKNOWN without that fact remains `RESEARCH_WSH_CLEANUP_RECOVERY_REQUIRED` indefinitely; elapsed time, retirement, restart or later success cannot clear it. UNKNOWN with this fact permits **regular only**, after every relevant predecessor cycle's `nextRegularAt`; it never permits fast retry. Published content and TTL remain unchanged.
- Runtime enabled/endpoint/permission/qualification preflight executes only after a confirmed durable STARTED ticket with `preflight_complete=false`. That pending preflight blocks preparation/binding immediately. Atomic `confirmWshPreflight` follows all checks, before connect/reservation/send. A failed negative publication leaves the durable hold. DEFERRED executes no runtime preflight and produces no new evidence; prior cache retains only its original TTL and existing rights/expiry checks. This is scheduled detection, not continuous runtime verification. Parser/authority/source/issuer identity checks remain before claim. Unknown claim commit aborts without connect; only exact readback can resolve it. No new failure-marker table or scheduling ordinals are introduced.
- Bookkeeping uses an absolute operation bound and the remaining original attempt deadline, including connection acquisition, lock waits, checks, publication, settlement and readback. Expiration destroys the owned database connection rather than leaving background writes running. Unknown commit remains unknown. Bounded rotation prevents two contended issuers from monopolizing due selection. Both metadata and event reservations must match the durable attempt account before any charge.
