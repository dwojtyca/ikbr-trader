## Outcome and boundaries

For each configured supported stock, external research consists of exactly Marketaux news and IBKR WSH calendar. Both refresh hourly and a proved successful acquisition remains usable for 24 hours. Required annual/periodic reports, SEC and issuer-report fetches, report publication deadlines, and mandatory financial metrics disappear from the new policy. Existing technical/candle preparation, verified issuer/listing/account/session identity, configuration admission, mandatory proposal-bound AI, deterministic risk, order ownership and unknown-outcome holds remain.

Startup uses fresh eligible current-manifest cache immediately. Missing or expired required coverage is prepared immediately when actual provider, pacing, cleanup and budget guards permit, then startup continues through its existing readiness gates. Hourly refresh continues independently of proposals and independently of the 24-hour freshness test. A valid three-hour-old cache can admit startup while an overdue refresh runs in the background; a completed or active current hourly cycle must not cause an extra request. Candle bootstrap may proceed in parallel. No new service-order or startup orchestration subsystem is needed.

This is an incremental policy extension, not deletion of report adapters or migration of history. No cross-manifest cache reuse, receipt relabeling, fabricated report data, new strategy, new AI provider, broker write path or automatic WSH recovery workaround is included. Existing WSH 10281 BUSY, original next-regular timestamps, cleanup and unknown fences are unchanged. A new manifest does not reset issuer pacing. Deployment to a new manifest needs ordinary fresh data under that manifest and can remain WAITING/HOLD for real provider failures.

## Strict policy and compatibility contract

It omits and rejects annual, periodic and bankCapitalMetric. Those remaining static identity/profile/currency facts do not become financial coverage requirements. Verified issuer provenance URLs remain truthful static evidence and are not fetched again. The new policy supports only the currently supported stock profile; it does not silently qualify ETFs or new listings.

Each instrument has exactly two distinct sources: one `marketaux-news` with roles exactly `["news"]` and the new Marketaux config below, and one `ibkr-wsh` with roles exactly `["calendar"]` and existing hourly WSH configuration (`refreshIntervalMs:3600000`, `maxAgeMs:86400000`). Source provider, issuer crosswalk, conId/listing, permission/retention and entitlement checks remain strict. Additional sources, reports role, duplicate roles, legacy Marketaux config in new mode, nonhourly WSH or missing either source are rejected. `refreshEnabled` must be true for this continuous mode.

New snapshots contain the current common identity/hash/timestamp/evidence/coverage/news/events fields plus the discriminator, and omit/reject reports/facts. ## Marketaux hourly acquisition contract

Introduce `parserConfig.kind: "marketaux-news-v2"` only for the new policy. Retain all v1 entity, qualification, entitlement, pageSize, maxPagesPerPass and maxArticles checks and fields. Add exact values `refreshIntervalMs:3600000`, `maxAgeMs:86400000`, `queryLookbackMs:86400000`; reject other combinations. The owner-confirmed ongoing source-validity records, original verifiedAt, qualification/evidence hashes and paid entitlement limits are preserved exactly. A finite source-validity member continues to cap use.

Use the existing bounded two-pass query algorithm with the selected one-hour slot. For slot `floor(admittedStartedAt / 3600000)`, query cutoff is `slot*3600000 - 1000`; queryStart is cutoff minus24h. Existing one-second query-bound padding, issuer entity filtering, pages, total-count/record-set agreement, response byte limits and canonical URL validation remain. The cutoff is provider query coverage, not acquisition completion or a claim that all cached articles are currently less than24h old. Diagnostics and AI retain actual publication timestamps and query bounds; a fixed hourly query cutoff can precede acquisition by up to roughly one hour.

New receipt kind `marketaux-news-v2` binds the exact admitted attempt ID, hourly slot, original queryStart/queryEnd/asOf, source identity/hash, qualification and entitlement hashes, page receipts and record-set proof, plus admitted startedAt and verified completedAt. `asOf` remains the original query cutoff. `coverage.windowStart/windowEnd` equal the original query bounds. `coverage.checkedAt` equals completedAt, obtained from the database clock after the complete acquisition has been validated and before its finite publication deadline; it is never supplied as an arbitrary caller timestamp. Every page fetchedAt is the database timestamp at which the bounded received response was durably recorded, ordered no later than completedAt and within the existing finite acquisition interval. It is not the host-clock timestamp returned by the HTTP helper. The original page content/hash and request identity remain bound to that response. Qualification must be effective at actual request/page/completion times. Do not falsely require the historical article query cutoff to be after a newly recorded ongoing confirmation; it is a search bound, not an access event.

Successful AVAILABLE or proved EMPTY coverage expires at original completedAt+86400000, capped by any finite qualification/entitlement deadline. Exactly24h is stale. Changing snapshot.createdAt, retaining a cache after failure, or emitting diagnostics must not extend this expiry. The new query/age relationship explicitly replaces the legacy `checkedAt===windowEnd` and window-end freshness assumptions only for receiptv2. Legacy receiptv1 validation remains exact.

Retain total acquisition<=120s, each request<=10s, two passes, byte/article/page caps, existing pooled account/provider atomic daily request/cost budgets, and no automatic retry after provider429. All actual requests reserve before send and record their original sanitized outcome. This package introduces no additional same-cycle Marketaux retry loop. Regular cadence is due no earlier than the prior admitted regular attempt start+1h and no more than one admitted attempt per hourly slot for that account/provider/verified issuer. Initial missing coverage with no active or inherited pacing fence is due now. Failed attempts consume their original slot/budget; restart, source ID changes or manifest adoption cannot manufacture a new attempt in the same admitted cycle. Existing legacy reservations remain counted in pooled budgets.

## Minimal durable Marketaux state and cache retention

Append `000035_marketaux_hourly_refresh.sql` (or the next unused sequential migration at integration). It introduces a narrow new-policy attempt ledger, not a replacement research scheduler. Persist immutable account/provider/issuer/source/config/manifest/instrument identity, canonical source hash, admitted slot/query window, database start, finite original deadline, attempt ID, terminal classification/sanitized error, and linked call/publication or retained snapshot identity. Use exact current authority and validated source identity at admission. The pacing ledger is `marketaux:ibkr-conid:<conId>`, using the qualified broker listing identity, not a mutable local issuer/source label or a selectable CIK/ISIN alias. Supporting additional listings remains outside this package. Serialize issuer admission across processes and manifests; after lock waits, re-read current authority, clock and cadence before admitting. Source hashes must use the same canonical bytes as TypeScript, not JSONB reserialization. Enforce immutable identity and monotone allowed state transitions in SQL and the store.

Attempt states are `STARTED`, `FINALIZING`, `SUCCEEDED`, `FAILED`, and `UNKNOWN`. Allowed transitions are STARTED→FINALIZING→SUCCEEDED/FAILED/UNKNOWN, or STARTED→UNKNOWN when interruption/ambiguity prevents complete finalization. Terminal states are immutable. Expired STARTED and all FINALIZING/UNKNOWN rows block use regardless of whether an asynchronous cleanup has updated the row. These semantics are mandatory:

- An actively running bounded read may coexist with an otherwise eligible original cache. This includes its exact linked reserved call while both call and attempt deadlines are unexpired and neither has an explicit UNKNOWN outcome. It is not evidence of a new success and cannot extend cache lifetime. An expired/unlinked call, explicit UNKNOWN, or FINALIZING state blocks admission.
- Before terminal result publication/retention, establish a durable finalization fence. Atomic terminal commit records the attempt outcome, all exact call-outcome links, and either new head/refresh slot or retained original snapshot/refresh slot. A crash, expired active attempt, unresolved call outcome, incomplete finalization or uncertain publication commit is HOLD. A lost terminal COMMIT reply remains uncertain until an authoritative read proves the exact atomically committed terminal row, original immutable snapshot/source projection and every linked call/response receipt. Complete proof resolves the uncertainty without replay; a changed head or terminal status alone is insufficient. Immediate readback uses the original operation budget. A later independently bounded preparation read may verify that same original commit, whose successful timestamp must still precede the original acquisition deadline; this is observation, never resumption of acquisition or a renewed TTL. Missing, partial or mismatched proof remains HOLD. Do not infer success from an absent error, a changed head or an in-memory catch.
- A fully proved success publishes new immutable coverage and supersedes prior AI bindings normally.
- A known terminal transient HTTP failure (429 or existing recoverable5xx classification), with all attempted call outcomes known and durably linked, can retain the exact previous current-manifest AVAILABLE/EMPTY news if that source projection remains eligible. Missing/stale WSH does not erase still-valid news; overall research remains unready until both sources pass. Record the failed attempt and retained snapshot ID/hash; preserve original news/evidence/coverage/check time and age. Do not republish old news as newly acquired or invent a successful receipt. Next regular attempt follows the original hour floor;429 is never retried immediately.
- Local budget exhaustion before any request, or after a wholly known successful prefix, may retain the same fresh cache only with durable budget-denial/known-prefix proof captured in the original atomic reservation, including its original UTC budget day. Rechecking a different day after midnight is not proof of that earlier denial. Missing/stale cache remains WAITING subject to actual budget availability; no increased cap or phantom reservation. Qualification/identity failure is not budget failure.
- Network failures whose existing outcome is UNKNOWN, unfinished calls outside the explicitly allowed unexpired active-read case, missing/mismatched call receipts, malformed or incomplete provider data, failed permission/entitlement, wrong issuer, future/expired source policy and unknown negative publication are not retention successes. They remain HOLD and cannot be hidden by a fresh cache. A typed terminal failure with no fresh cache cannot make READY.
- No operator-unreviewed retry of unknown work is added. New-policy unknown attempts are not swept into legacy Marketaux recovery exceptions. Legacy original UNKNOWN recovery semantics are unchanged.

Implement one shared new-mode admission/provenance check used by startup preparation, bind/validateBinding (including execution's final use-time check), and diagnostic state. Pure snapshot eligibility is necessary but cannot waive a newer durable hard/unknown failure. Apply locks in a documented order compatible with existing authority, reservation and head locks; never hold a transaction during network I/O. Prove concurrent refresh, finalization, binding and adoption behavior in isolated PostgreSQL. Adoption must reject active/finalizing/unresolved new-mode attempts, while retaining existing historical unknown checks and ordinary finite recovery rules; no wholesale history cleanup.

Errors from either terminal operation must not be retried as provider requests or overwritten by a generic cache-retention catch.
